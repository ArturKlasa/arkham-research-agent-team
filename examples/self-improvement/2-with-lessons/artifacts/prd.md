# prd (product)

## overview

A stdlib-only Python (3.7+) HTTP JSON API over an in-memory mock book database. It serves GET /books, GET /books/<id> and GET /books?author=X. It has JSON error handling and a unittest suite. Out of scope: persistence, write endpoints, auth, pagination, sorting, other filters, production hardening, TLS, third-party dependencies, OpenAPI.

## requirements

- **id**: R1; **text**: The service uses only the Python standard library (http.server ThreadingHTTPServer/BaseHTTPRequestHandler, json, urllib.parse); no third-party dependencies.; **acceptance**: Static inspection of all source and test imports shows only stdlib modules; the project has no requirements/dependency file listing third-party packages; the server starts on a clean Python 3.7+ install.
- **id**: R2; **text**: An in-memory mock dataset of 8 to 10 books, each with int id, string title, string author and int year. Ids are unique. Pure functions list_books(), get_book(id) and search_by_author(name) are provided.; **acceptance**: A unit test asserts the dataset has 8-10 records, each with exactly those fields and types, ids unique; and that the three functions return the expected results.
- **id**: R3; **text**: GET /books returns 200 with a JSON array of all books.; **acceptance**: Integration test: GET /books returns status 200 and a body that parses to a list equal to the full dataset.
- **id**: R4; **text**: GET /books/<id> with an existing integer id returns 200 and that single book as a JSON object.; **acceptance**: Integration test: GET /books/<existing id> returns 200 and a JSON object equal to that book record.
- **id**: R5; **text**: GET /books/<id> with a valid integer id that does not exist returns 404 with JSON body {"error": <message>}.; **acceptance**: Integration test: GET /books/99999 returns 404 and a body that parses to an object containing a string "error" key.
- **id**: R6; **text**: GET /books/<id> with a non-integer id returns 400 with JSON body {"error": <message>}.; **acceptance**: Integration test: GET /books/abc returns 400 and a JSON object with a string "error" key.
- **id**: R7; **text**: GET /books?author=X returns 200 with a JSON array of books whose author contains X as a case-insensitive substring; an empty array if none match. The value is URL-decoded (spaces, unicode).; **acceptance**: Integration tests: a known author name returns the expected books; a differently-cased partial name returns the same; a non-matching name returns 200 and []; a URL-encoded name with a space matches correctly.
- **id**: R8; **text**: Unknown routes return 404 with a JSON error body; non-GET methods (e.g. POST, PUT, DELETE) return 405 with a JSON error body.; **acceptance**: Integration tests: GET /nope returns 404 with JSON "error"; POST, PUT and DELETE to /books each return 405 with JSON "error".
- **id**: R9; **text**: Every response, including errors, has Content-Type application/json; charset=utf-8 and a Content-Length equal to the byte length of the body. Errors are written by a custom JSON writer, not send_error. User input is never echoed into headers.; **acceptance**: Integration tests check, for 200, 404, 400 and 405 responses, that the Content-Type header equals application/json; charset=utf-8 and int(Content-Length) equals len(body bytes).
- **id**: R10; **text**: The server entry point accepts configurable host and port, defaulting to 127.0.0.1:8000, and the handler's request logging is suppressed or overridden so it does not clutter test output.; **acceptance**: Running the entry point with no args listens on 127.0.0.1:8000; passing host/port arguments changes the bind address; the test run prints no per-request log lines.
- **id**: R11; **text**: A unittest suite covers data-layer unit tests and integration tests against a live server started on port 0 in a thread, shut down with shutdown() and server_close() in tearDown/tearDownClass.; **acceptance**: `python -m unittest` exits 0, runs tests covering R2-R9, finishes without hanging, and uses no fixed port.
- **id**: R12; **text**: A short README documents run and test commands (python -m unittest), routes, JSON shape, status codes, search semantics and trailing-slash behaviour.; **acceptance**: README exists and contains the run command, the test command, all three endpoints, the error codes 400/404/405, the case-insensitive substring rule and a statement of trailing-slash behaviour.
