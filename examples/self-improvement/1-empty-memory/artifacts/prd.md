# prd (product)

## overview

PRD for a stdlib-only Python HTTP JSON API over an in-memory mock book database. It has read-only endpoints for listing books, getting a book by id, and searching by author. It includes JSON errors, unittest tests and a README. Assumes Python 3.7+. Out of scope: third-party dependencies, persistence, write endpoints, auth/TLS/rate limiting, pagination/sorting/other search fields, Docker/CI.

## requirements

- **id**: R1; **text**: Use only the Python standard library; no third-party dependencies or frameworks. Target Python 3.7+.; **acceptance**: Static check of all source and test files shows every import resolves to a stdlib module; the project has no requirements/dependency file listing third-party packages.
- **id**: R2; **text**: Provide an in-memory mock book dataset of about 5-10 books, each with id (int), title, author and year, in books/data.py.; **acceptance**: A unit test loads the dataset and asserts 5-10 books, each with exactly the keys id (int), title (str), author (str), year (int), and with unique ids.
- **id**: R3; **text**: Provide a data-access layer with all(), get(id) and search_by_author(name). get returns None for a missing id. search_by_author is case-insensitive substring matching.; **acceptance**: Unit tests: all() returns every book; get(existing) returns that book; get(missing) returns None; search_by_author('TOLK') and 'tolk' return the same books as the full author name; a non-matching name returns [].
- **id**: R4; **text**: GET /books returns 200 with a JSON array of all books.; **acceptance**: Integration test requests /books and asserts status 200 and a body equal to the full dataset as a JSON list.
- **id**: R5; **text**: GET /books/<id> with an integer id of an existing book returns 200 and that book as a JSON object. A query string on this route is ignored.; **acceptance**: Integration test requests /books/1 and asserts 200 and the body equals book 1; /books/1?x=y returns the same.
- **id**: R6; **text**: GET /books/<id> for an integer id that does not exist returns 404 with a JSON error body.; **acceptance**: Integration test requests /books/99999 and asserts status 404, Content-Type application/json, and a body that parses as a JSON object containing an 'error' key.
- **id**: R7; **text**: GET /books/<id> with a non-integer id returns 400 with a JSON error body.; **acceptance**: Integration test requests /books/abc and asserts status 400 and a JSON object body with an 'error' key.
- **id**: R8; **text**: GET /books?author=<name> returns 200 with a JSON list of books whose author contains the name, case-insensitively. No matches returns 200 with [].; **acceptance**: Integration tests: a full-name query, a differently cased query and a partial-substring query each return the expected books; a non-matching name returns status 200 and body [].
- **id**: R9; **text**: Unknown routes return 404 with a JSON error body. Non-GET methods (POST, PUT, DELETE, PATCH) return 405 with a JSON error body.; **acceptance**: Integration tests: GET /nope returns 404 with a JSON 'error' body; POST, PUT and DELETE to /books each return 405 with a JSON 'error' body.
- **id**: R10; **text**: All responses, including errors, have Content-Type: application/json and an accurate Content-Length. Errors are written manually as JSON, not via send_error.; **acceptance**: Integration tests assert for success and error responses that Content-Type is application/json and Content-Length equals the byte length of the body; no response body is HTML.
- **id**: R11; **text**: Implement the server with http.server ThreadingHTTPServer and a BaseHTTPRequestHandler subclass, parsing path and query with urllib.parse. Data is injected via the server attribute. It binds to 127.0.0.1 on a configurable port, with an entry point to run it. The handler overrides log_message to suppress logging. Untrusted input is never echoed into headers.; **acceptance**: Code inspection and tests confirm: the handler reads data from self.server; running the entry point with a port argument serves on 127.0.0.1:<port>; the test suite produces no request log lines on stderr; a request with CR/LF-encoded author input yields no extra headers.
- **id**: R12; **text**: Include unittest tests: pure data-layer tests plus integration tests that start the server on port 0 in a background thread using urllib.request and clean up with shutdown and server_close.; **acceptance**: `python -m unittest` from the repo root exits 0, runs both data-layer and integration tests covering R3-R10, and leaves no running threads or open ports.
- **id**: R13; **text**: Provide a short README with run and test instructions (python -m unittest), the routes, the schema, the search semantics, and a note that http.server is not production-grade.; **acceptance**: README exists and contains the run command, the `python -m unittest` command, all three endpoints, and the production-grade caveat.
