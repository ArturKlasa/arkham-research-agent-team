# prd (product)

## overview

A stdlib-only Python HTTP JSON API over an in-memory mock book database. It offers list all books, get a book by id (JSON 404 if missing) and search books by author name (case-insensitive substring), with unittest unit tests and a short README. Out of scope: fuzzy, regex or accent-insensitive matching, write endpoints, auth, pagination, sorting, persistence, third-party dependencies, production hardening, TLS, keep-alive tuning, a separate authors resource, combining author search with other filters.

## requirements

- **id**: R1; **text**: The service uses only the Python standard library (http.server ThreadingHTTPServer and BaseHTTPRequestHandler, json, urllib.parse; unittest and urllib.request in tests).; **acceptance**: Static inspection of all imports in source and test files shows only standard-library modules; no requirements file lists third-party packages.
- **id**: R2; **text**: The mock database is an in-memory list of dicts, each with id (int), title (str), author (author name str) and year (int).; **acceptance**: A data-layer test asserts every record has exactly these keys with the stated types, and the dataset has at least 3 books, with at least two sharing an author and at least one author name containing a space.
- **id**: R3; **text**: GET /books returns 200 with a JSON array of all books.; **acceptance**: An HTTP test requests /books and asserts status 200 and that the parsed body is a list equal to the full dataset.
- **id**: R4; **text**: GET /books/{id} for an existing integer id returns 200 with that book object.; **acceptance**: An HTTP test requests /books/1 and asserts status 200 and the body equals the book with id 1.
- **id**: R5; **text**: GET /books/{id} for an id that does not resolve to a book (unknown integer or non-integer) returns 404 with body {"error": "not found"}.; **acceptance**: HTTP tests request /books/99999 and /books/abc and assert status 404 and parsed body == {"error": "not found"} for each.
- **id**: R6; **text**: GET /books?author=<name> returns 200 with a JSON array of books whose author name contains the query as a case-insensitive substring, or an empty array if none match. Percent-encoded values (e.g. spaces) are decoded. An empty author value matches all books; a missing author parameter returns the plain list.; **acceptance**: HTTP tests assert: a full-name query returns exactly the matching books; a different-case query returns the same; a partial name matches; a URL-encoded name with spaces matches; a non-matching name returns status 200 and []; ?author= returns all books.
- **id**: R7; **text**: Unknown routes return the same JSON 404 {"error": "not found"}.; **acceptance**: An HTTP test requests /nope and asserts status 404, JSON Content-Type and body {"error": "not found"}.
- **id**: R8; **text**: All responses, including 404s, have Content-Type application/json; charset=utf-8, a UTF-8 encoded body and an accurate Content-Length. Author values are never placed in headers.; **acceptance**: HTTP tests for 200 and 404 responses assert the Content-Type header value and that Content-Length equals the number of body bytes read.
- **id**: R9; **text**: Data-layer functions (list all, get by id, filter by author name) are separate from the HTTP handler and callable without a server.; **acceptance**: Unit tests call these functions directly and check: list returns all books; get by id returns a book or None for a missing id; filter returns matches for a hit, partial match and different case, and an empty list for a miss.
